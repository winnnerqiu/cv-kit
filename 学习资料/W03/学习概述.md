## 二、四个任务包

### 📦 任务 1：手写 2D 卷积（3~4 小时）★ 核心

**文件**：`练习/W03/w3_conv.py`

**要填**：`conv2d_sliding`（滑窗）、`conv2d_im2col`（矩阵乘）

**思维转变**（和 W2 一脉相承，但更进一层）：

| W2 学到的 | W3 要会的 |
| --- | --- |
| 把「逐像素的循环」换成「整张图一起算」 | 把「核在每个位置滑动」换成「一次取所有窗口」 |
| 工具：`arr[:, :, 0]`、广播 | 工具：`sliding_window_view`、`einsum`、`im2col` |

**核心代码只有三行**（写对这三行，其余都是细节）：

```python
padded  = np.pad(img.astype(np.float64), p, mode="reflect")   # 边界
windows = sliding_window_view(padded, (k, k))                 # 一次拿到所有窗口
out     = np.einsum("ijkl,kl->ij", windows, kernel)            # 一次算完所有位置
```

**必须亲自验证的四个概念**（每个都会在面试里出现）：

| 概念 | 要知道什么 |
| --- | --- |
| padding | cv2 默认 `BORDER_REFLECT_101` ↔ `np.pad(mode="reflect")`；`reflect` 和 `symmetric` 差在**边沿像素算不算镜像轴** |
| 输出尺寸 | `stride=1` 时 `p = k//2` 输出和输入同尺寸；`stride=2` 时约减半 |
| `einsum` 下标 | `"ijkl,kl->ij"` 读法：i、j 保留，k、l 求和——**就是卷积的定义式** |
| im2col | 窗口摊平成矩阵再乘，代价是内存 **k² 倍**，换来 BLAS 速度 |

**验收**：4 种核（Sobel / 均值 / 随机 ×2）全部 PSNR ≥ 45 dB，且 im2col 与滑窗结果**完全相同**。

> 实测：正确实现能做到 **PSNR = ∞**（逐像素完全一致）。所以 45dB 是宽松线，
> 过不了就是逻辑有 bug，别放过。

### 📦 任务 2：均值 / 高斯 / 中值滤波（2~3 小时）

**文件**：`练习/W03/w3_filters.py`

| 滤波器 | 核心运算 | 擅长 | 代价 |
| --- | --- | --- | --- |
| 均值 | 窗口内**求平均** | 快、简单 | 糊边缘；脉冲噪声只是被"摊薄" |
| 高斯 | 窗口内**加权**平均，中心权重最大 | 平滑还保结构 | 要算核；对脉冲噪声无力 |
| 中值 | 窗口内取**中位数** | 专杀椒盐噪声，几乎不糊边 | 排序开销大 |

**两个必踩的坑**（不踩这两个，PSNR 上不去）：

**坑 1：高斯核必须归一化**
不除以总和时，5×5 核的矩阵总和约 16，卷积后整张图被放大十几倍 → 一片白 → **PSNR 只有 6 dB**。

**坑 2：σ 与 ksize 的对应关系**
cv2 的规则是 σ=0 时自动推算：

```
σ = 0.3 × ((ksize - 1) × 0.5 - 1) + 0.8
ksize=3 → σ=0.8    ksize=5 → σ=1.1    ksize=7 → σ=1.4    ksize=9 → σ=1.7
```

用错这个公式，核形状就不对，**PSNR 掉到 5~6 dB**。这是 W3 最容易被忽略的知识点。

**坑 3：中值的边界模式**
`cv2.medianBlur` 用 `BORDER_REPLICATE`（numpy 里是 `mode="edge"`）。
用成 `reflect` 时形状没错，但边缘一圈会和 cv2 差 1 个灰阶（约 0.1% 像素，PSNR 仍有 78~81 dB）。
**想拿满分就试出正确的 mode。**

**验收**：均值/中值 ≥ 50 dB，高斯 ≥ 55 dB。

> 实测参考值：均值 ∞、中值 ∞（边界选对）、高斯 63.7 dB。
> 高斯做不到 ∞ 是因为 **cv2 内部把核量化成定点数**，和纯浮点计算必然有微小差别——
> 这正是要写进「差异原因」的一条。

### 📦 任务 3：直方图均衡 + CLAHE（3~4 小时）★ 最难

**文件**：`练习/W03/w3_histogram.py`

这一包的函数**都已写好**（CLAHE 的插值代码是最难的部分，先给完整参考），
你的任务是**跑通 + 读懂 + 改着玩**，把观察写进报告。

**HE 在做什么**：让像素值在 0~255 上尽可能均匀分布 → 对比度拉开。

```
LUT[v] = round( (cdf[v] - cdf_min) / (N - cdf_min) × 255 )
```

**HE 的两个毛病**：① 全局化，局部细节被牺牲；② 直方图尖峰被放大，噪声显现。

**CLAHE 的两个对策**：
① **自适应**：切成 8×8 块，每块单独 HE
② **限制对比度**：每块直方图超过 `clip_limit` 的部分削平，削掉的数量平摊回整个直方图

**插值：CLAHE 的最后一公里**

不做插值直接拼块，交界处会出现明显的**网格状亮暗带**（相邻块 LUT 不同，
同一灰度在块 A 映射到 90、在块 B 映射到 130）。
解法是每像素用周围 4 块的 LUT 做**双线性插值**。

| 版本 | PSNR vs cv2 | 最大差 | >10 灰阶的像素 | 肉眼 |
| --- | --- | --- | --- | --- |
| 不做插值 | **27.5 dB** | 34 | **31.5%** | 明显网格 |
| 双线性插值 | **47.0 dB** | 4 | 0.00% | 看不出 |

**插值价值 19.6 dB** —— 这就是「最后一公里」的量化答案。

**TODO B/C/D**（填空题变成了思考题）：

- **B**：把 `use_interpolation` 改成 `False` 再跑，对比 PSNR 和差异图
- **C**：clip_limit 从 1 调到 40，**输出标准差反而下降、与原图相关性变差**——为什么？
- **D**：把 LUT 公式改错一处（比如去掉 `cdf_min`），看 PSNR 掉多少

**验收**：HE 逐像素一致（∞）；CLAHE ≥ 30 dB（参考实现 47.0 dB）。

## 七、W3 的坑预警（提前告诉你，省得卡住）

| # | 坑 | 症状 | 解法 |
| --- | --- | --- | --- |
| 1 | 高斯核没归一化 | PSNR 只有 5~6 dB，图像全白 | `kernel /= kernel.sum()` |
| 2 | σ 公式用错 | 同上，PSNR 5~6 dB | 用 cv2 的自动公式（见任务 2 坑 2） |
| 3 | 卷积用了 uint8 | 溢出回绕，图像一片黑/白 | 先 `astype(np.float64)` |
| 4 | 用 `astype` 而不是 `rint` | 系统性偏 1 个灰阶，PSNR 掉到 48 左右 | `np.clip(np.rint(x), 0, 255).astype(np.uint8)` |
| 5 | 中值边界用 reflect | 边缘一圈差 1，PSNR 77~81 | 试 `mode="edge"` |
| 6 | CLAHE 插值用 reflect pad | PSNR 崩到 11 dB | 用 `mode="edge"` |
| 7 | CLAHE 索引写错 | 内存报错要 47 GiB | 用 `take_along_axis` 取每像素的 LUT |
| 8 | `einsum` 下标写反 | 形状不对或结果错 | `"ijkl,kl->ij"`，k、l 是要消掉的核维度 |

> 这些坑**都是我在准备材料时真踩过的**（CLAHE 插值那两个尤其隐蔽），
> 所以给你的时候已经修好了。你踩到别的坑记得记下来，这是最有价值的产出之一。
