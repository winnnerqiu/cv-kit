## 三、学到的核心知识（可复述才算掌握）

### 图像与像素

| 知识 | 具体内容 |
| --- | --- |
| 图片的三种模式 | `RGB`（3 通道）/ `L`（单通道灰度）/ `RGBA`（3 通道 + alpha） |
| 像素的表示 | 一个像素 = `(R, G, B)` 三元组，每个分量 0~255 |
| 坐标系 | 原点在**左上角**；PIL 用 `px[x, y]`（**x 在前**）；编号从 0 开始，右下角是 `(w-1, h-1)` |
| 尺寸的两种写法 | PIL：`img.size` → `(宽, 高)`；NumPy：`arr.shape` → `(高, 宽, 通道)` |
| 灰度公式 | `Y = 0.299R + 0.587G + 0.114B`（加权平均，系数和为 1） |

### Python 语法（实战中用到）

模块导入 / 变量与命名 / int·float·str·bool·tuple / 元组解包 / 函数定义与 `return` / 条件分支 / 双重循环 / 异常处理 / 列表（浅层）/ f-string / `__main__` 守卫

### 工程习惯

- **CLI 的价值**：用 `argparse` 接收参数，别人不用改代码就能用
- **commit 的粒度**：一次一件事，说明写成 `feat:` / `docs:` / `chore:`
- **仓库装"配方"不装"产物"**：`.gitignore` 挡住 `out/`
- **边界情况清单化**：坏文件、非图片、特殊模式，逐个明确处理策略

## 四、踩过的坑（每条都值得记）

| # | 坑 | 真相 | 教训 |
| --- | --- | --- | --- |
| 1 | 新建了文件，终端跑它"没反应" | 文件是 **0 字节**（新建 ≠ 有内容，且没存盘） | 编辑器里 tab 上的**圆点 = 未保存**；用 `cat` 一眼看文件内容 |
| 2 | `Connection refused` 连不上 GitHub | Windows hosts 被写入 27 条 `127.0.0.1 xxx.github.com` | `getent hosts github.com` 返回 `127.0.0.1` 就是被污染 |
| 3 | 凭据管理器报 `/mnt/c/Program: not found` | 路径**含空格**且配置时用双引号，引号被 shell 吃掉 | 配置值里的空格要写 `\ `（反斜杠转义） |
| 4 | `IndentationError` 卡住 | 某行缩进 3 个空格（应为 4） | Python 靠缩进定层级；用 `Shift+Tab` 整块调整，别手数 |
| 5 | `FileNotFoundError: 'out/...'` | `save()` 不会自动创建目录 | 输出前先 `mkdir(parents=True, exist_ok=True)` |
| 6 | 坏 JPEG 能 `open()` 成功 | `Image.open()` 只读文件头，**不读像素** | 异常处理必须包住"取像素"那一步 |
| 7 | 终端出现 `>` 提示符，敲什么都没反应 | 多打了一个引号，引号没配对 | `Ctrl + C` 退出等待状态 |
| 8 | `NameError: name 'Image' is not defined` | 忘了 `from PIL import Image` | 看到 NameError 先查 import 和拼写 |

> 网络与 Git 的完整排查过程见：`00-踩坑记录-网络与Git.md`
