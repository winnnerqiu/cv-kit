# cv-kit

图像处理算法的 Python 复现库。目标是把常用算子手写一遍，并与 OpenCV 的实现做精度和性能对标。

## 环境

- Python 3.11（conda 环境 `vision`）
- 依赖：Pillow

## 安装

conda activate vision
pip install pillow

## 用法

python grayscale_cli.py <输入目录> [输出目录]

例：
  python grayscale_cli.py testdata           # 结果默认输出到 out/
  python grayscale_cli.py testdata out2      # 指定输出目录
  python grayscale_cli.py -h                 # 查看帮助

处理规则：只处理 .jpg / .jpeg / .png / .bmp，输出统一为同名的 `_gray.png`。

## 灰度算法

采用 ITU-R BT.601 亮度公式（与 OpenCV 的灰度转换同源）：

  Y = 0.299R + 0.587G + 0.114B

三个系数之和为 1，因此 Y 天然落在 [0, 255]。这里手写双重循环实现，未调用
`Image.convert("L")` —— 目的是给后续的向量化实现（W2）留一个可对比的基准。

取整方式：`int()` 截断（与 OpenCV 的 `cv2.cvtColor` 行为一致，便于 W3 对标）。

## 已处理的情况

| 情况 | 处理 | 说明 |
| --- | --- | --- |
| RGBA（带 alpha 通道） | 先合成到白底，再转灰度 | 丢弃 alpha 会把透明区域按黑色处理，整图偏暗 |
| L（单通道） | 直接透传，不套公式 | R=G=B 时公式恒等，重算是无用功；且单通道像素是标量，解包会报错 |
| 非图片文件 | 按扩展名跳过 | 避免与真正的解码失败混在一起 |
| 文件损坏 | 捕获异常、打印警告、继续 | 批量处理的容错要求 |
| 输出目录不存在 | 自动创建 | 保证脚本可重复运行 |

## 实测

| 输入 | 像素数 | 耗时 |
| --- | --- | --- |
| 640×480 | 307,200 | 0.05 s |
| 1920×1080 | 2,073,600 | 0.36 s |

批量处理 6 个条目（4 成功 / 2 跳过）：0.64 s。像素数增加 6.75 倍，耗时增加约 7 倍，
即当前实现的耗时与像素数近似线性（约 5.7 万像素/秒）。

## 已知限制

- 输出统一为 PNG，不保留原始扩展名。
- 取整使用 `int()` 截断，逐像素会比四舍五入系统性地偏暗不到 1 个灰阶。
- 性能受纯 Python 循环限制，大图处理慢（W2 将用 NumPy 向量化解决）。
- 不递归子目录。

## 记录

- `Image.open()` 只解析文件头，不读像素数据。截断的 JPEG 能通过 `open()`，
  但会在取像素时抛异常 —— 因此异常处理必须覆盖读取像素的那一步，而不是 `open()`。
- `Image.save()` 不会创建不存在的目录，需要提前 `mkdir(exist_ok=True)`。
- Python 用缩进定义代码块，同一块内缩进量必须一致。
